## Как работать (важно)
Работай как внимательный инженер, а не как генератор кода:
1. **Сначала читай.** Перед правкой файла прочитай его целиком и посмотри, кто его использует (`grep`). Не предполагай структуру — проверяй.
2. **Задача больше одного файла — сначала короткий план** (какие файлы, в каком порядке, как проверишь), потом код.
3. **Минимальный диф.** Делай только то, что просит задача. Не переименовывай, не форматируй и не «улучшай» соседний код.
4. **Стиль проекта.** Повторяй существующий стиль: комментарии в коде редкие и по делу, имена английские, UI-тексты русские. Не добавляй зависимости без необходимости.
5. **Доказательства, а не уверенность.** Перед словом «готово» запусти `npm test`, `npm run lint`, `npm run build` и покажи итог. Если что-то упало — скажи об этом прямо, с выводом. Не пиши «должно работать».
6. **UI проверяй в браузере** (`npm run dev`, затем открой страницу): типы и тесты не ловят визуальные поломки. Если не можешь открыть браузер — так и скажи.
7. **Необратимое — только с разрешения владельца:** коммиты, push, удаление файлов, деплой, `git reset --hard`, `--force`. Ключи и `.env*` не читай в вывод и не коммить.
8. **Не угадывай факты.** Имя модели, API Google/Supabase, версии библиотек — сверяй с документацией; если не можешь проверить, пометь как непроверенное.
9. **Отчёт.** В конце: что сделано, что проверено (команды и результат), что НЕ проверено, какие есть риски. Коротко, без воды.

## Окружение
- Windows 11, PowerShell. Переменные окружения задаются `$env:VAR="x"`, а не `VAR=x cmd`. Пути с кириллицей — в кавычках.

- Git: окончания строк CRLF/LF дают предупреждения — это нормально, не «чини» их массовой правкой.

## 3. Валидация ответов Gemini и удаление `any`
**Проблема.** `extractJson<T>` делает `JSON.parse(...) as T` без проверки схемы. `payload: any` в `callGemini` и другие `any` (смотри `grep -rnE ": any|as any" src`).

**Что сделать.**
- `npm i zod`. Для каждого ответа (упражнение каждого типа, урок целиком) описать zod-схему рядом с типами и использовать `schema.safeParse`. При ошибке — понятное сообщение пользователю и одна автоматическая повторная попытка.
- Убрать все `any`: заменить на конкретные типы или `unknown` + сужение.
- Пустые `catch` (например в `ClassroomWhiteboard.tsx`, строки ~33, 69, 76) — либо логировать, либо убрать неиспользуемый параметр.
